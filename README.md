# Ashen Roads

## Run

Run the launcher from the **Ashen Roads project folder**: the folder that directly contains `index.html`, `server\server.js`, and `START-ONLINE.bat`. If the downloaded folder contains another `ashen_roads_online_v15_43` folder, open that inner folder first. Double-click `START-ONLINE.bat` (or `tools\start-game.bat`) and keep its window open; Live Server (port 5500) only serves static pages and cannot run login or multiplayer. If port 8000 is busy, the Node server chooses the next available port (up to 8010) and opens that address.

## Petrol bomb (v15.49)
- **5** = Petrol bomb (3 at the start, orange-beam loot gives +2). Left click / ATK = throw. The fire burns ~10 s where it lands: zombies burn, and so do you if you stand in it.

## Project layout

- `assets/models/` contains the dog, environment, player, vehicle (Nissan R34, Ford Escort), weapon, and zombie models.
- `assets/textures/zombies/` contains zombie textures.
- `assets/audio/` is reserved for audio assets; current game audio is generated with the Web Audio API.
- `css/style.css` contains the game styles.
- `js/main.js` contains the game logic.
- `js/rigs/` contains the player and dog rigs.
- `js/vendor/` is reserved for local vendor scripts; Three.js is currently loaded from a CDN in `index.html`.
- `tools/` contains the Windows launchers.

## Accounts / login
Open the game -> you land on the login page. New player: **CREATE ACCOUNT** with a username and password; the account is created immediately with no email or verification code. Already have an account: **LOGIN**. Then the normal menu / lobby opens and your account name is your player name.

### Where the accounts are saved: the `database/` folder
Next to `index.html` there is a **`database/`** folder. The server writes every account there:
- `users.json` - username, password **hash** (never the real password), created time, wins
- `players.csv` - the same list as a table you can open in Excel (no passwords)
- `secret.key` - signs the login tokens (keep private)

The web server refuses to send anything from `database/`, `server/` or `.env`. Back the folder up. (Accounts made by v15.37-v15.40 in `server/data/` are copied into `database/` automatically on the first start.)

### Sign-up flow (first time on a device)
The login page opens on **CREATE ACCOUNT**. Choose a username and password; the account is created and you are signed in immediately. Later visits go straight in (or use the LOGIN tab).

After registration, the browser keeps the login token and automatically opens the game on later visits; tokens last 365 days by default (`TOKEN_DAYS` can override this). Logging out or clearing browser storage requires logging in again on that device. The account itself works on any device, but each device needs its own first login.

## Admin and player activity
To enable the private dashboard, create/register the admin account first, then set the backend environment variable `ADMIN_USERNAME` to that exact username and restart the server. Sign in with that account and use the **ADMIN** link to open `admin.html`. The dashboard shows live rooms and connected players, registered usernames, saved activity (last login, logins, play time, matches, deaths, wins, an activity log and an Excel/CSV download), and the top five multiplayer winners. Email addresses from older accounts may still appear. The admin API rejects requests from any other account; leaving `ADMIN_USERNAME` unset disables it. Multiplayer wins are recorded by the backend when only one registered account remains alive in a room.

## Live hosting WITH working accounts (Render + free Upstash database)
Free hosts (Render free, Heroku ...) **delete their disk on every restart / deploy / sleep**. A plain `users.json` would lose every account, so for live hosting keep the accounts in a free online database:
1. Go to https://upstash.com -> sign up (free) -> **Create Database** (Redis, any region, free plan) -> open it -> section **REST API** -> copy **UPSTASH_REDIS_REST_URL** and **UPSTASH_REDIS_REST_TOKEN**.
2. On Render: your Web Service -> **Environment** -> add `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` -> Save. After registering your admin account, also set `ADMIN_USERNAME` to that exact account name. (`AUTH_SECRET` is already generated by `render.yaml`; accounts AND the login-token key are stored in Upstash.)
3. Deploy. The Render log must say `Auth: accounts are stored in the remote database (Upstash)`. If it says `users.json ... WILL BE LOST` the two Upstash variables are missing.
4. Open your `https://...onrender.com` address and create an account with a username and password. Redeploy / restart the service and log in again to check - the account is still there.
Other hosts: same two variables (also works with `KV_REST_API_URL` / `KV_REST_API_TOKEN`). A VPS or a Render *paid* persistent disk can instead keep `users.json`: set `DATA_DIR` to the disk path. Run only ONE server instance (rooms live in memory anyway).
First visit after the free server slept takes up to ~1 minute - the login page says "waking up" and continues by itself.

## Netlify frontend + online server
Netlify serves static files; it cannot run this project's persistent Node.js/WebSocket server. Deploy the frontend to Netlify and run `server/server.js` as one Node web service (for example on Render):
1. Configure the Node service as described above, set `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` for durable accounts, and keep the generated `AUTH_SECRET`.
2. Set the backend `ALLOWED_ORIGINS` to the exact Netlify site origin, for example `https://ashen-roads.netlify.app` (no trailing slash). Leave it unset only if you deliberately want to accept WebSocket connections from any site.
3. Before deploying the static site, edit `js/server-config.js` and set `window.ASHEN_SERVER_URL` to the backend's HTTPS origin, for example `https://ashen-roads.onrender.com`. Do not put database credentials in this frontend file.
4. Deploy the project folder to Netlify. `netlify.toml` serves the static frontend and blocks public access to `/server/*`, including the local token-signing key.
5. Test the Netlify login page with a newly registered account, then reload and log in again. Open the Netlify URL in two browser profiles/devices, create/join the same room, and confirm both reach the match.

Accounts are stored on the Node backend, not in Netlify or the browser. The browser only keeps its login token on the Netlify site origin. Multiplayer rooms are held in server memory, so use one backend instance; two separate server instances will not share rooms.

## Online multiplayer
1. Install Node.js (https://nodejs.org), then double-click `START-ONLINE.bat` in the game folder (or `tools/start-online.bat`, or run `node server.js` inside the game folder). No npm install needed.
2. Open the address printed in the server window (normally `http://localhost:8000/`; if that port is busy, the server chooses the next available port through 8010). Friends on the same Wi-Fi use the printed LAN address. Always open the game FROM this server.
3. Type a name + the same room code, press PLAY ONLINE. Enter = chat, Y = reply to last message, N = mic on/off.
4. For friends over the internet: forward port 8000, or host the folder on a VPS / use a tunnel (e.g. cloudflared). Microphone needs localhost or https.

5. Everybody must open the SAME server address (e.g. http://<host-LAN-IP>:8000/) and press PLAY ONLINE with the same room code. The first press reloads the page once so the city is built identically for every player.
6. Multiplayer flow: open lobby.html (start-online.bat does this) -> everybody enters the same ROOM code (INVITE button copies a link) -> everybody presses READY -> shared countdown -> everybody loads -> everybody starts at the same time.
7. CREATE ROOM gives a short room code - share it (COPY ROOM CODE / INVITE LINK). Friends press JOIN ROOM and type that code.

## Play with friends who are NOT on your Wi-Fi (put the game on the internet)
The game server is one Node.js file, so any Node host works. Easiest free way (Render.com):
1. Put this whole folder in a GitHub repo (New repository -> upload files).
2. On render.com: New -> Web Service -> connect that repo. Render reads `render.yaml` / `package.json` (start command `node server/server.js`). Free plan is fine.
3. When it is live you get an address like `https://ashen-roads.onrender.com`. Open it, press CREATE ROOM, press COPY ROOM CODE and send the text to your friends. They open the same address, press JOIN ROOM and type the code.
(Railway / Fly.io / any VPS work the same: run `node server/server.js`, it uses the PORT the host gives it. wss:// is handled automatically on https.)
Friends on the SAME Wi-Fi do not need hosting: run tools/start-online.bat, press CREATE ROOM, COPY ROOM CODE already contains your LAN link.

## Server settings (environment variables, all optional)
MAX_PLAYERS (8), MIN_PLAYERS (2), CD_MS (6000), LOAD_TIMEOUT (90000), HOP_GRACE (60000), END_GRACE (10000), `TOKEN_DAYS` (365), `ADMIN_USERNAME` (unset disables admin), ALLOWED_ORIGINS (comma list), TURN_URL/TURN_USER/TURN_PASS.
Run the tests with `npm test` (Node 22+).
